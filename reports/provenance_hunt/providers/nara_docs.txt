A null cap means fair-use (no hard daily ceiling).</p></div></div></div><div class="nara-card"><div class="nara-card__body"><div class="nara-stack nara-stack--col nara-stack--gap-1"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">Per-class daily token quotas</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">Each model belongs to a quota class — base, Lite, Mocin, or Pro — and each class has its own daily token quota. A subscription gets a separate daily quota for every class it can access, and the quotas are independent: using a model only counts against its own class quota and never reduces another. When one quota is exhausted, models in the other classes you have still work until the quotas reset at the start of the next day.</p></div></div></div><div class="nara-card"><div class="nara-card__body"><div class="nara-stack nara-stack--col nara-stack--gap-1"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">Concurrency</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">Plans also bound how many requests may run at once. A flagged request is rejected locally with a clear message — the upstream provider never sees it. This protects the shared upstream accounts behind the gateway and keeps the service available for everyone.</p><div class="nara-stack nara-stack--col nara-stack--gap-3"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">What is screened</p><div class="nara-table-wrapper"><table class="nara-table"><thead><tr><th style="width:32%">Category</th><th>What triggers a rejection</th></tr></thead><tbody><tr><td><p class="nara-text nara-text--sm nara-text--semibold nara-text--body">Offensive-security build</p></td><td><p class="nara-text nara-text--sm nara-text--regular nara-text--body">A request to build attack tooling or malware — for example an authorization frame (&quot;authorized pentest&quot;) wrapped around exploit development, C2 frameworks, credential theft, detection evasion, or an end-to-end attack chain.</p></td></tr><tr><td><p class="nara-text nara-text--sm nara-text--semibold nara-text--body">Child safety (CSAM)</p></td><td><p class="nara-text nara-text--sm nara-text--regular nara-text--body">Any request involving sexual content concerning minors. This category is rejected outright and results in immediate account action upstream, so it is enforced strictly.</p></td></tr><tr><td><p class="nara-text nara-text--sm nara-text--semibold nara-text--body">Credential exfiltration</p></td><td><p class="nara-text nara-text--sm nara-text--regular nara-text--body">A request to echo or reproduce a secret-shaped value verbatim (an API key, private key, or access token). Ordinary configuration code that merely references a key name is not affected.</p></td></tr><tr><td><p class="nara-text nara-text--sm nara-text--semibold nara-text--body">Weapons &amp; critical infrastructure</p></td><td><p class="nara-text nara-text--sm nara-text--regular nara-text--body">A request to build weapons or CBRN material, or to attack critical infrastructure (power grid, water supply, SCADA). Discussion of the same topics is not affected — only build/attack requests.</p></td></tr></tbody></table></div><div class="nara-card nara-card--glass nara-card--compact"><div class="nara-card__body"><p class="nara-text nara-text--sm nara-text--regular nara-text--body">The screens are conservative: ordinary coding, security-defense work (detection rules, threat intel, patching), and education are not affected. Only transcripts that clearly read as a build-the-attack request, or as sexual content involving minors, are rejected.</p></div></div></div><div class="nara-stack nara-stack--col nara-stack--gap-3"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">Response on a blocked request</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">A blocked request returns the standard error envelope with HTTP 400 and type validation_error. Adjust the request content instead.</p></div></div></div></div></section><div role="separator" aria-orientation="horizontal" class="nara-divider nara-divider--horizontal"></div><section class="nara-stack nara-stack--col nara-stack--gap-5" aria-labelledby="combos"><div class="nara-inline nara-inline--gap-2 nara-inline--align-center nara-inline--justify-between nara-inline--wrap"><h2 class="nara-heading nara-heading--2" id="combos" style="scroll-margin-top:5.5rem">Model combos</h2></div><p class="nara-text nara-text--base nara-text--regular nara-text--muted">Model combos are user-owned virtual model ids of the form combo/&#x27;&lt;name&gt;&#x27; that bundle multiple real models under one fallback strategy. When the first model in the panel fails, the combo automatically falls over to the next one — perfect for keeping free models resilient.</p><div class="nara-stack nara-stack--col nara-stack--gap-3"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">What is a combo?</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">A combo bundles 1-5 model aliases under a single combo/&#x27;&lt;name&gt;&#x27; id. Requests to that id are routed to the panel models in order: if the first model fails, the combo immediately tries the next one within the same request. A Redis-backed circuit breaker tracks failures across requests so a known-bad model is skipped before the engine is even called.</p></div><div class="nara-stack nara-stack--col nara-stack--gap-3"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">How fallback works</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">When you call combo/&#x27;&lt;name&gt;&#x27;, the gateway tries each panel model one-by-one within the SAME request: target 1 → if it fails (402, 403, 500, timeout) → release billing → target 2 → if it fails → target 3, and so on. The first target that succeeds returns its response. If all targets fail, the combo returns the last error.</p></div><div class="nara-stack nara-stack--col nara-stack--gap-3"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">Circuit breaker</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">A circuit breaker prevents the combo from repeatedly hitting a model that is down. After a failure, the circuit for that model opens for a 10-minute cooldown — during which that model is skipped immediately (no engine call wasted). After the cooldown expires, the model is retried. A successful request closes the circuit and resets the counter. Deterministic failures (402 insufficient balance, 403 not entitled) open the circuit immediately; transient failures (500, timeout) require 3 consecutive failures before opening.</p></div><div class="nara-stack nara-stack--col nara-stack--gap-3"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">Fallback strategy</p><p class="nara-text nara-text--sm nara-text--regular nara-text--muted">Panel models are tried top-to-bottom in the order you configure them. Put your most reliable model first and use the others as safety nets. Circuit-open targets are skipped before the engine is called, so a known-down model costs zero latency.</p></div><div class="nara-stack nara-stack--col nara-stack--gap-2"><p class="nara-text nara-text--base nara-text--semibold nara-text--body">Example request</p><div class="nara-codeblock"><div class="nara-codeblock__head"><span class="nara-codeblock__lang">bash</span><button type="button" class="nara-codeblock__copy"><svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-copy size-3.5" aria-hidden="true"><rect width="14" height="14" x="8" y="8" rx="2" ry="2"></rect><path d="M4 16c-1.1 0-2-.9-2-2V4c0-1.1.9-2 2-2h10c1.1 0 2 .9 2 2"></path></svg>Copy</button></div><pre class="nara-codeblock__pre" aria-label="Example request" tabindex="0"><code>curl https://router.bynara.web.id/v1/chat/completions \
